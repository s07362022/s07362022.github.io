🎯 面試情報：STA 觀念＋文字處理 Scripting＋APR 高頻題

準備優先順序：先能清楚回答 rise/fall time、setup/hold、slack、skew，再熟悉 APR full flow；最後練習用 Tcl／Python／grep／awk 從 report 找 WNS、TNS、endpoint 與 ERROR。這類職缺通常不是只問「會不會跑工具」，而是看你能不能理解 report、快速定位問題並自動化。

1. Rise / Fall Time（訊號邊緣）

Rise time 是訊號由低到高所需時間，常以 10%→90% 衡量；fall time 則是 90%→10%。兩者合稱 transition time 或 slew。

Slow slew → gate delay↑、短路功耗↑、下一級 timing 變差

常見修法：upsizing driver、插 buffer、降低 fanout／load、縮短 wire。

2. Setup / Hold（FF 採樣窗口）

Setup：clock edge 前 data 要先穩定，檢查 max delay；Hold：edge 後 data 要繼續穩定，檢查 min delay。

Setup fail = data 太慢
Hold fail = data 太快

Setup 常加速 data path；Hold 常插 delay buffer。降低頻率通常只幫 setup，不直接修 hold。

3. Text Processing（CAD 基本功）

工具每天產生大量 log/report，CAD 會用 scripting 自動抓錯誤、彙整 QoR、比較 regression。

grep：篩選行
awk：取欄位／統計
sed：取代文字
Tcl/Python：完整 flow 與 parser

面試常要求：找最差 slack、統計 violation、列出 endpoint、掃描 ERROR/WARNING。

K01 如何讀一條 Timing Path？WNS、TNS、Slack 各代表什麼？ ▼
一條 register-to-register path 可拆成：launch clock path → launch FF clock-to-Q → combinational cell/net delay → capture FF setup/hold requirement → capture clock path。讀 report 時先確認 scenario 與 path group，再看 startpoint、endpoint、path type、arrival time、required time、slack，最後才決定修法。
欄位意義面試重點
Arrival timeData 實際到達 endpoint 的時間由 launch clock、C2Q、cell delay、net delay 組成
Required timeData 必須到達或保持的界線受 period、setup/hold、capture clock、uncertainty 影響
SlackTiming margin負值是 violation；setup 常寫 required−arrival，hold 由工具依 min check 計算
WNSWorst Negative Slack最嚴重單一路徑的 violation
TNSTotal Negative Slack所有負 slack endpoint 的總和，反映問題廣度

Debug 順序

  1. 確認 clock、mode、corner、exception 與 path type 是否正確。
  2. 判斷主要是 cell delay、net delay、clock skew、uncertainty 還是 SI delta delay。
  3. 看 logic depth、fanout、transition、capacitance、route length 與 congestion。
  4. 找共同 root cause：同一 driver、同一 macro channel、同一 clock branch 或同一 endpoint group。
面試加分：WNS 好但 TNS 很差，代表最差路徑不深，卻有大量 endpoint fail；只修 top-1 path 不一定能有效收斂。
K02 Clock latency、skew、uncertainty、jitter 與 CTS 的關係是什麼？ ▼
  • Source latency：clock source 到 design clock definition point 的延遲。
  • Network / insertion latency：clock definition point 到 FF clock pin 的延遲。
  • Skew：launch FF 與 capture FF 的 clock arrival 差。
  • Jitter：clock edge 隨時間變動；通常被納入 clock uncertainty。
  • Uncertainty：為 jitter、modeling margin、variation 等保留的 timing budget。
Pre-CTS 常用 ideal clock 加估計 latency/uncertainty；CTS 後使用 propagated clock，實際 clock cells、wire RC 與 skew 會進入 timing。Positive skew，也就是 capture clock 較晚到，通常幫 setup但傷 hold；negative skew 通常相反。

CTS 不只追求 skew 最小

  • 控制 insertion delay、clock transition、capacitance、fanout、duty cycle 與 clock power
  • 處理 clock gating cell、generated clock、macro clock pin 與不同 skew group
  • Useful skew 可借 timing margin，但必須同時驗證 setup/hold 與所有 corners
回答「CTS 就是讓所有 clock 同時到」太簡化。真實 CTS 是 timing、power、skew、latency、DRV 與 routing resource 的多目標最佳化。
K03 PVT、RC Corner、MMMC、OCV、AOCV/POCV、CPPR 分別是什麼？ ▼
名詞作用
PVTProcess、Voltage、Temperature 改變 cell delay 與 leakage。
RC corner不同金屬 R/C 條件改變 net delay；setup/hold 的 worst RC 不一定相同。
MMMCMulti-Mode Multi-Corner，同時驗證 functional/test modes、PVT、RC 與 constraints。
OCV以 early/late derate 模擬晶片內局部 variation。
AOCVDerate 依 path depth 與 physical distance 調整，比固定 OCV 少一些不必要悲觀。
POCV用統計 variation 模型計算 delay sigma，advanced node 常見。
CPPR移除 launch/capture clock 共用路徑被重複套用 early/late variation 的悲觀量。
Slow corner 通常讓 setup較 tight，fast corner 通常讓 hold較 tight；但 temperature inversion、clock/data derate、RC、SI 與 path topology 都可能改變實際 worst scenario，因此 signoff 要看完整 MMMC，而不是只背 SS/FF。

檢查重點

  • 每個 active scenario 是否有正確 library、RC corner、SDC 與 operating condition
  • 是否存在 unconstrained endpoints 或錯誤 disable timing
  • APR 與 signoff STA 的 WNS/TNS 是否可合理 correlation
K04 Floorplan 為什麼重要？Utilization、macro placement 與 congestion 怎麼取捨？ ▼
Floorplan 決定後續 PPA 的上限。Macro、IO、power domain 與 routing channel 一旦規劃不佳，後面即使換 cell 或重跑 optimization，也可能無法解決長線、壅塞與供電問題。

核心考量

  • Core utilization：過高會缺乏 buffer/ECO 空間並造成 congestion；過低則增加 area、wire length 與 clock/power cost。
  • Macro placement：依 data flow、pin direction、power pin、clock/reset 關係安排，不是固定「全部靠邊」就最好。
  • Halo/channel：保留 std-cell 與 routing 空間；channel 寬度要考慮兩側 pin density 與可用 layers。
  • Pin placement：依 connectivity 與 package/interface 位置減少 crossing、feedthrough 與 detour。
  • Blockage：hard/soft/partial blockage 用來控制合法擺放與局部 density。

Congestion debug

  1. 看 global-route overflow 與 heat map。
  2. 區分 macro channel、pin access、high fanout、placement density 或 PG blockage。
  3. 調 macro/orientation/channel、降低局部 density、spread cells、改 pin、buffer tree 或 layer usage。
  4. 重跑 timing，因 detour 與 spreading 可能改變 setup/hold。
K05 Power Network 怎麼規劃？IR Drop 與 EM 分析應該看什麼？ ▼
PDN 通常由 package bump/pad、top-level mesh、ring、stripe、macro PG pin、standard-cell rail 與 vias 組成。目標是在可接受的 routing resource 與 area 下，把電壓穩定送到每顆 cell，並確保金屬與 via 的 current density 不超標。
分析在看什麼常見根因
Static IR平均／穩態 current 下的 voltage dropstripe 太疏、路徑太長、via/PG 漏接
Dynamic IR瞬間 simultaneous switching 與 dI/dtclock edge 集中、局部高 activity、decap 不足
EMwire/via current density 與 lifetime線寬不足、via 數太少、電流集中

改善方法與副作用

  • 加寬／加密 stripe、增加 vias、改善 bump/pad 分布，可降低 R 並分流。
  • 加入 decap 可支援瞬間電流，但會占 placement area並增加 leakage。
  • 重新分散高功耗 cells 或調 macro，可改善 hotspot，但可能影響 timing/congestion。
  • 增加 PG metal 會吃掉 signal-routing tracks，因此修 IR/EM 後必須重查 congestion、DRC 與 timing。
K06 Routing、RC Extraction、Crosstalk 與 Physical Signoff 如何串起來？ ▼
  1. Global routing：估算每區 routing demand/capacity、layer 使用與 overflow。
  2. Detail routing：實際配置 tracks、vias、spacing，滿足 foundry rules。
  3. RC extraction：從 layout 抽取每條 net 的 resistance、ground capacitance 與 coupling capacitance。
  4. SI-aware STA：依 aggressor switching window 計算 victim 的 delta delay 與 noise。
  5. Physical signoff：檢查 DRC、LVS、antenna、density、ERC，以及 STA、IR/EM。
Crosstalk 來自 coupling capacitance：反向切換常使 victim變慢而傷 setup，同向切換可能使 victim變快而傷 hold；quiet victim 也可能產生 glitch。常見修法是 spacing、shielding、換 layer、減少平行長度、buffer、driver sizing 或 reroute。

Route 後常見修復

  • Timing ECO：size/buffer、route optimization、useful skew
  • DRV：max transition/cap/fanout repair
  • DRC：reroute、via change、spacing/enclosure repair
  • Antenna：diode、jumper/layer hopping、reroute
K07 SDC Constraints、False Path、Multicycle Path、CDC 與 Recovery/Removal 有什麼關係？ ▼
  • Clock：create_clock、generated clock、uncertainty、latency、transition 定義 timing基準。
  • IO constraints：input/output delay、driving cell、load 描述 block 外部環境。
  • False path：功能上不需 timing 的 path；不能只因 timing 難修就設 false。
  • Multicycle path：功能規格允許多個 cycles；setup放寬後通常要配套設定 hold。
  • CDC：非同步 clock domain 要靠 synchronizer/FIFO/handshake；STA exception不能取代 CDC verification。
  • Recovery/Removal：async reset/set 相對 clock edge 的檢查，概念類似 setup/hold。
最危險的不是 violation，而是 unconstrained path 或錯誤 exception，因為工具可能顯示 timing clean，但真實晶片沒有被正確檢查。

面試回答順序

先說功能意圖 → 再說 constraint → 用 CDC/STA report 驗證 → 最後做 exception review。不要從「消除 violation」倒推 exception。

K08 Synthesis、LEC 與 Low-Power Verification 在 CAD flow 中如何銜接？ ▼
Synthesis 把 RTL 依 library 與 SDC 映射成 gate-level netlist；LEC 確認 RTL 與 netlist 在允許的轉換下功能等效；Low-power flow 再依 UPF/CPF 插入或驗證 isolation、level shifter、retention 與 power state 行為。

常見交付與檢查

  • Synthesis：mapped netlist、SDC、QoR、area/power report、scan/clock-gating資訊
  • LEC：compare points、unmapped/abort points、black box、constant與renaming setup
  • UPF：power domain、supply set、power switch、isolation strategy、retention strategy、PST
  • APR handoff：確認 physical-only cells、tie cells、spare cells 與 low-power cells 的處理規則
CAD 角色：把上述工具串成可重複、可追蹤、能在不同 node/project 切換的 flow，並建立 regression 保證工具升版後結果沒有異常漂移。
K09 Timing ECO 的完整流程是什麼？為什麼不能只看修前修後 Slack？ ▼
  1. 鎖定 signoff scenario、violating path group 與 root cause。
  2. 選擇最小影響修法：setup 用 size/LVT/buffer/route/useful skew；hold 用 delay cell/downsize/HVT/detour。
  3. 將 ECO 變更落實到 APR database，legalize、route 並重新 extraction。
  4. 重跑 MMMC STA、SI、DRV、power/congestion、DRC 與必要的 IR/EM。
  5. 若改到邏輯功能或 netlist connectivity，重跑 LEC/Formality/Conformal。
  6. 輸出 ECO script、change list、before/after QoR 與可回溯版本。
Local slack 變好不代表 ECO 成功：新增 buffer 可能造成 routing congestion、power 上升、另一個 corner 的 hold fail、max transition 或 DRC。Signoff看的是整體 closure。
K10 一個可靠的 CAD Automation Flow 應該有哪些設計？ ▼
可靠的 flow 不只是把 commands 串起來，而是能重現、能失敗得清楚、能比較版本差異，並讓不同 project/node 用設定檔切換而不必複製整套 script。
  • Configuration：design/node/tool version/corner 與路徑集中管理，避免 hard-code。
  • Pre-check：檔案、library、license、disk、constraint 與 environment sanity check。
  • Stage contract：每一 stage 有明確 input/output、done marker、return code 與 restart機制。
  • Log/report parser：擷取 ERROR/FATAL、WNS/TNS、area、power、congestion、runtime、memory。
  • Regression：與 golden baseline 比較，設定合理 threshold，避免工具升版造成 silent regression。
  • Traceability：Git commit、tool version、command line、host、timestamp、config snapshot 全部可回溯。
  • Testing：parser unit test、小設計 smoke test、代表性 blocks nightly regression。

語言分工

Tcl 操作 EDA database；Python 做複雜 parsing、JSON/CSV、資料分析與 dashboard；Shell/awk 做 job control、檔案與快速 filter。選工具依工作，不需要全部塞進同一支 script。

M01 請你詳細描述 APR flow。 ▼
APR 是把 synthesis 產生的 gate-level netlist，經過實體規劃、擺放、clock tree、繞線與 signoff，最後輸出可 tapeout 的 GDS/OASIS。我的回答會依序說明每個 stage 的輸入、目標與檢查項目。
  1. Design Import / Setup：讀入 netlist、SDC、Liberty、LEF、RC tech、UPF 與 MMMC views；先做 library、link、unconstrained path 和 connectivity sanity check。
  2. Floorplan：決定 die/core size、aspect ratio、utilization、macro／IO placement、halo、channel、blockage 與 voltage domain。
  3. Power Planning：建立 VDD/VSS ring、stripe、rail、power via 與 macro PG connection；先做 PG connectivity、early IR drop 與 EM 檢查。
  4. Placement / Pre-CTS Optimization：擺放 standard cells，處理 legality、density、congestion、max transition/cap/fanout 與 setup timing。此時 clock 通常仍以 ideal clock 分析。
  5. CTS：插入 clock buffer/inverter，控制 skew、insertion delay、transition、capacitance 與 clock power；CTS 後改用 propagated clock，開始重點檢查 hold。
  6. Routing：先 global route 評估資源，再 detail route 形成實際金屬與 vias；處理 DRC、SI/crosstalk、antenna 與 timing。
  7. Post-route Optimization：以 extracted RC 做 setup/hold ECO、SI repair、DRV repair，並確認修一個 corner 不會破壞其他 scenario。
  8. Signoff / Tapeout：完成 STA、DRC、LVS、antenna、IR/EM、density、DFM 與 equivalence 檢查，最後輸出 GDS/OASIS。
30 秒版：Import → Floorplan → Power Plan → Placement → CTS → Routing → Post-route ECO → Signoff。每一站都持續追 timing、congestion、power integrity 與 physical verification，而不是到最後才一次檢查。

M05 請解釋 IR drop 和 Antenna effect，並提出解決方法。 ▼

IR drop

電流流過具有電阻的 power network 會產生 Vdrop = I × R。Cell 實際拿到的電壓降低後，delay 會增加，嚴重時可能造成 setup failure 或功能錯誤。Static IR 偏向平均/穩態負載；dynamic IR 則關注大量 cell 同時切換造成的瞬間壓降。
  • 降低 R：加寬／加密 power stripe、縮短供電路徑、增加 vias
  • 降低或分散 peak I：調整 placement、加入 decap、改善 power bump/pad 分布
  • 修完重跑 IR/EM，確認 congestion 與 area trade-off

Antenna effect

在 plasma etching 製造期間，長金屬累積電荷並透過 MOS gate 放電，可能破壞 gate oxide。這是製造階段的可靠度問題，不是晶片操作時的無線天線效應。
  • 插入 antenna diode，提供安全放電路徑
  • 使用 jumper／layer hopping 將長金屬分段
  • Reroute 或調整連接順序，再跑 antenna rule check
一句話區分：IR drop 是晶片運作時供電網路上的電壓損失；antenna 是晶圓製造期間金屬充電可能傷害 gate oxide。
M06 若 Setup time 與 Hold time violation，你會如何解決？ ▼
我不會一看到負 slack 就直接換 cell。第一步會先確認 constraint、clock、corner 與 path type 正確，再把 delay 拆成 cell delay、net delay、clock skew 與 uncertainty，找出真正瓶頸。
Violation本質常見修法
SetupData 太晚到，max-delay check failUpsize／LVT、buffer high-fanout、縮短 route、logic restructuring、減少 congestion、useful skew；架構層可 pipeline 或降低頻率
HoldData 太早到，min-delay check fail插 delay cell/buffer、downsize／HVT、route detour、調整 useful skew；通常不靠降低頻率解決

修完一定要檢查

  • Setup fix 是否在 fast corner 製造 hold violation；hold fix 是否傷到 setup
  • 所有 MMMC scenarios、SI、OCV、recovery/removal 是否仍 clean
  • Max transition/cap/fanout、power、congestion、legal placement 與 DRC
常見錯誤：只背「setup 換大 cell、hold 加 buffer」。面試官更想聽到你會先定位 cell delay、net delay、skew、constraint 或 congestion 根因，並做跨 corner 回歸。

📊 QoR 到底在看什麼？（面試必懂）

QoR = Quality of Results，量化「這顆晶片設計結果好不好」的成績單。核心是 PPA：Power、Performance、Area 三個互相拉扯的目標。

指標看什麼單位合格條件屬於
WNS
Worst Negative Slack		 最差那條 path 有沒有違規 ps ≥ 0（才能 tapeout） Performance
TNS
Total Negative Slack		 所有違規 path 的 slack 加總 ps = 0 Performance
Area 佔多少矽面積 µm² 越小越好，需符合 die size budget Area
Leakage
Static Power		 靜止時的漏電（HVT vs LVT 差 10×） µW 符合功耗規格 Power
Dynamic Power 切換時 C×V²×f 的電流 mW 符合散熱與電池需求 Power
Congestion 繞線塞車（routing overflow %） % = 0（>5% 就需要重做 floorplan） 實體

三個互相拉扯的例子

要更快（WNS 收緊）
→ 用 LVT（低 Vt）大 cell
→ 漏電 ↑、面積 ↑
要更省電（Leakage↓）
→ 換 HVT cell、clock gate
→ timing 可能違規（WNS↓）
要更小（Area↓）
→ 共用資源、刪 buffer
→ timing 可能不過、congestion↑

CAD 工程師如何改善 QoR

  • 換 synthesis strategy：調 effort level、mapping option、retiming
  • Cerebrus ML 探索：自動跑上百種 strategy 組合，找 Pareto front
  • Multi-Vt 優化：critical path 用 LVT，其餘換 HVT → timing 過 + 省電
  • SDC 品質：constraint 不對，QoR 再好都是假的
  • Timing ECO：在不動 function 的前提下局部 size up/down
面試 20 秒口條：
「QoR 就是 PPA 的量化成績——timing 看 WNS/TNS 有沒有違規、area 看面積有沒有超預算、power 看漏電跟動態功耗。三個互相拉扯，CAD 工程師的工作是在 constraint 範圍內找最好的平衡點，用 Genus 不同 strategy 或 Cerebrus 的 ML 探索找 Pareto-optimal 解。」

🟢 STA 面試題（PrimeTime / Tweaker / PrimeClosure）

T01 Setup time 和 Hold time 的物理意義是什麼？violation 怎麼修？ ▼
Setup time：FF 採樣 clock edge 前，data 必須已經穩定的最短時間；它是 maximum-delay check。
　Violation → data 太晚到。修法：減少 logic depth、cell upsizing、換 LVT、插 buffer 改善大負載、縮短繞線、pipeline；架構允許時可增加 clock period／降低頻率。

Hold time：FF 採樣 clock edge 後，data 必須繼續穩定的最短時間；它是 minimum-delay check。
　Violation → 新 data 太早到。修法：加 delay buffer、cell downsizing／換 HVT、增加 route delay，並檢查 clock skew。
  • 核心公式：slack = required time − arrival time；負 slack 就是 violation
  • Setup 受 clock period 影響；hold 是同一個 edge 附近的檢查，因此降低頻率通常不能直接修 hold
  • Positive skew（capture clock 較晚）通常幫 setup、傷 hold；negative skew 通常相反
修 timing 不能只看單一 path：upsizing 雖可改善 setup，卻可能增加 power、congestion，甚至在其他 corner 製造 hold 問題。
T02 你用 PrimeTime 做 timing signoff，流程是什麼？ ▼
1. 讀入 netlist、parasitic（SPEF）、SDC
2. 設定 MMMC：create_scenario 分 setup / hold 各 corner
3. update_timing → report_timing -slack_lesser_than 0 找 violators
4. 分析 path：startpoint → logic cells → endpoint → slack breakdown
5. timing ECO：用 fix_eco_timing -setup（PT-ECO 功能）或手動 ECO Tcl
6. 收斂後：report_qor 確認 WNS/TNS / 全 scenario 均 clean
7. Signoff 文件存 report、截圖 WNS=0

Tweaker / PrimeClosure 分工

  • Tweaker：在 place 完後、route 前，做 timing-driven 修改（cell sizing、buffer insertion）
  • PrimeClosure：post-route signoff-level closure，整合 PT 做最終 ECO iteration
T03 什麼是 False Path 和 Multicycle Path？什麼時候用？ ▼
  • False Path：不存在功能上的時序關係。例如：不同 clock domain 的 CDC 路徑、test mode 路徑。
    set_false_path -from [get_clocks CLK_A] -to [get_clocks CLK_B]
  • Multicycle Path：data 跨越多個 clock cycle 才 capture。例如：pipeline 中某條路允許 2 cycle。
    set_multicycle_path 2 -setup -from FF_A -to FF_B
    set_multicycle_path 1 -hold -from FF_A -to FF_B（hold 要補回 1）
常見錯誤：設 multicycle 忘記補 hold constraint → hold violation 大爆。
T04 Timing / Power ECO 怎麼做？你有沒有跑過 ECO 的經驗？ ▼
ECO（Engineering Change Order）分三種：
1. Timing ECO：cell sizing up/down、buffer insertion/removal，不動 logic function
2. Power ECO：size down non-critical cell、swap to HVT（高 Vt，省電）
3. Function ECO：RTL 改變 → LEC 驗證等效性 → ECO patch 到 netlist

PT 做 Timing ECO 範例

  • fix_eco_timing -setup -end_point_clock_filter {CLK}
  • 產出 eco.tcl，APR team 再 implement
  • ECO 後重跑 LEC 確認 function 不變
T05 Rise time / Fall time 是什麼？和 Setup / Hold 有什麼不同？ ▼
Rise time 是訊號由低電位上升到高電位的 transition 時間，常見量測區間為 10%→90%；fall time 是 90%→10%。它們描述的是訊號邊緣快慢，也常稱為 slew。

Setup / Hold 描述的是 flip-flop 在 clock edge 前後要求 data 穩定的時間窗口。也就是說，rise/fall 是「波形品質」，setup/hold 是「採樣時序要求」。

為什麼 slow transition 不好？

  • 下一級 cell delay 增加，setup timing 可能變差
  • PMOS/NMOS 同時導通較久，short-circuit power 增加
  • 可能超過 library 的 max_transition constraint
  • 常見修法：upsize driver、插 buffer、減少 fanout/load、縮短 net
30 秒回答：Rise/fall time 是 signal transition 的速度；setup/hold 是 FF 對 data 穩定窗口的要求。Slow slew 會增加 cell delay 與功耗，也可能造成 max-transition violation。
T06 PVT、OCV、MMMC 為什麼需要？Setup 和 Hold 通常看哪些情境？ ▼
  • PVT：Process、Voltage、Temperature 會改變 cell 與 wire delay。
  • OCV：同一顆晶片不同位置也可能有 variation，launch/capture path 不會完全一起快或一起慢。
  • MMMC：Multi-Mode Multi-Corner，同時覆蓋 functional/test modes 與不同 RC/PVT corners。
  • 傳統直覺是 setup 偏向 slow corner、hold 偏向 fast corner；但 advanced node 必須以 library、RC corner 與 signoff scenario 定義為準，不能只背 SS/FF。
回答順序：先說 variation 來源 → 為何單一 corner 不夠 → MMMC 如何覆蓋 → 最後說用每個 scenario 的 WNS/TNS 和 unconstrained path 做 signoff。

🟠 LEC / LowPower 面試題（Conformal / UPF）

L01 LEC（Logical Equivalence Checking）的原理是什麼？什麼時候做？ ▼
LEC = 形式驗證：把兩個設計版本（Golden vs Revised）做 Boolean equivalence check，不用跑模擬，窮舉所有輸入組合。

何時用 LEC：
• Synthesis 後：RTL vs gate-level netlist
• ECO 後：old netlist vs new netlist
• Scan insertion 後：function 應不變

Conformal 基本 flow

  • 讀 Golden（RTL）和 Revised（netlist）
  • set dofile setup.do 設定 library、clock、constant
  • read design -Golden …; read design -Revised …
  • map points; verify → report verified

Mismatch debug

  • 先看 report not_mapped：有 unmapped 通常是 clock cell 或 tie cell 問題
  • 看 report not_verified：function mismatch，追 key point
  • 常見原因：SDC false path 影響 LEC、ECO 套錯版本
L02 UPF low power design flow 解釋一下，有哪些特殊 cell？ ▼
UPF（Unified Power Format）定義 power domain、電壓域切換、省電策略。
關鍵 cell 類型：
• Isolation cell：domain 關閉時，把輸出箝位到安全值（0 or 1）
• Level shifter：不同電壓 domain 之間的訊號轉換（VDD1 → VDD2）
• Retention FF：power down 時保留 state，用 shadow latch + backup supply
• Power switch（MTCMOS）：實際斷電用的 header/footer cell
• Always-on buffer：even in power-down domain，確保 control path 存活

常見 debug

  • Isolation cell 放錯位置 → functional X propagation
  • Level shifter 方向錯（LH vs HL）→ signal corruption
  • Retention FF save/restore sequence 錯 → 值不對
L03 低功耗設計方法有哪些？Conformal LP check 在檢查什麼？ ▼

低功耗技術層次

  • Clock gating：關閉不必要 FF clock → 省動態功耗，最簡單
  • Power gating：整個 domain 斷電（MTCMOS），省靜態漏電
  • Multi-Vt：critical path 用 LVT（快），非 critical 用 HVT（低漏電）
  • DVFS：動態電壓頻率調整，需要硬體架構支援
  • operand isolation：ALU input 不改變時 gate 掉

Conformal Low Power Check 驗什麼

  • UPF 與 netlist 的 power domain 一致性
  • Isolation cell 是否覆蓋所有 cross-domain port
  • Level shifter 方向與位置正確
  • Retention FF save/restore protocol 合法性

A02 Floorplan 時你怎麼規劃 macro placement？有什麼原則？ ▼
  • 靠邊放：macro 推到 die 四周，避免切斷 std-cell row
  • Pin 對準：macro pin 朝向 std-cell 區，減少 routing detour
  • Halo / keepout：macro 周圍保留空隙，防止 congestion
  • 同功能 macro 聚集：減少 long wire，例如 SRAM 靠近 CPU
  • Channel routing：macro 之間留足夠 routing channel（尤其 metal 1–3）
  • Power domain：同 domain macro 放在一起，減少 isolation cell 數量
可以提到昨天準備的示意圖：「macro 圍邊、std-cell 在中間」 → 這正是慧榮 SSD 控制晶片的典型 layout。
A03 CTS 的目標是什麼？Clock skew 和 clock latency 有什麼差？ ▼
Clock latency：clock 從 source 到 FF clock pin 的絕對延遲（source latency + insertion delay）

Clock skew：同一 clock domain 不同 FF 的 latency 差值。
　Local skew = |T_clk_A − T_clk_B|（相鄰 FF）
　Global skew = max − min（整個 domain）

CTS 目標：最小化 skew（通常 < 100 ps at 28nm），同時控制 total capacitance（省 power）
  • Useful skew：故意讓 borrowing path 的 FF 晚一點，幫忙 setup
  • Skew 過大 → hold violation（需要補 buffer）
  • Innovus ccopt_design = concurrently optimize CTS + timing
A04 IR drop 分析在什麼時機做？IR drop 太大怎麼改？ ▼
時機：Power plan 後做 static IR drop（快速），route 後做 dynamic IR drop（含 switching 電流）

Static IR drop：用 Voltus / RedHawk，基於 DC 電流分佈
Dynamic IR drop：模擬 clock edge 時 simultaneous switching → 瞬間 dI/dt

IR drop 過大修法

  • 加 VDD/VSS stripe 密度（更多金屬 bar）
  • 換用 wider wire（resistance↓）
  • 加 decap cell（局部電荷補充）
  • 調整 clock 邊緣時序（減少同步切換）
  • 重新 floorplan macro（讓 power pin 離 power ring 更近）
A05 什麼是 Crosstalk？它如何造成 delay 或 noise？ ▼
相鄰且長距離平行的金屬線之間會形成 coupling capacitance。正在切換並造成干擾的 net 稱為 aggressor，被影響的 net 稱為 victim。

Delay effect：兩者反向切換時，victim 常看到較大的有效電容而變慢，可能傷 setup；同向切換時可能變快，進而影響 hold。
Noise effect：victim 原本靜止，aggressor 的切換仍可能耦合出 glitch，若超過 noise margin 就可能被錯誤判讀。

常見修法

  • 增加 spacing、減少長距離平行走線
  • 以 VDD/VSS shielding，或將 nets 分配到不同 layer
  • 插 buffer 切短長 net、upsize victim driver、適度 downsize aggressor
  • 重跑 SI-aware routing / timing analysis，確認所有 MMMC scenario
口訣：先說 coupling，再分 delay/noise，最後說 spacing、shielding、buffer、reroute。
A06 Antenna effect 是什麼？為什麼是製造問題？怎麼修？ ▼
Antenna effect 不是晶片操作時接收到無線訊號，而是 plasma etching 製造期間，長金屬累積電荷並經由 MOS gate 放電，可能破壞很薄的 gate oxide。Foundry 會用 metal area／perimeter 相對 gate area 的 antenna ratio 設限。
  • Antenna diode：提供安全放電路徑
  • Jumper / layer hopping：把長金屬切段，提早換到尚未形成的高層金屬
  • Reroute：縮短違規 metal，或調整連接順序讓 diffusion 先接上
面試不要回答「加 shielding」：shielding 主要處理 crosstalk，不是 antenna violation 的標準修法。
A07 2.5D / 3D IC 是什麼？實體設計多了哪些挑戰？ ▼
2.5D IC：多顆 die 並排在 silicon interposer 上；3D IC：多顆 die 垂直堆疊，透過 TSV、micro-bump 或 hybrid bonding 連接。優點是 die-to-die 距離短、頻寬高，也能把不同 process node 的 chiplet 整合在一起。

APR / CAD 額外要處理

  • Die partition、bump/TSV planning 與跨 die connectivity
  • Die-to-die timing、clock synchronization、SI 與 power delivery
  • 堆疊造成的 thermal hotspot、mechanical stress 與 IR drop
  • Known-good-die、DFT/test、封裝 parasitic 與整體 yield
30 秒回答：3D IC 用垂直互連縮短距離並提高 bandwidth，但 CAD flow 必須把 package、thermal、power、跨 die timing 和 test 一起分析，不能只看單一 die。
A08 Placement 或 Routing congestion 怎麼判斷？怎麼改善？ ▼
Congestion 是某區域 routing demand 大於可用 track capacity。常見現象是 global-route overflow、繞線 detour、DRC 增加、wire delay 變大，最後讓 timing 與 runtime 一起惡化。
  • 先看 congestion map，確認是 macro channel、pin access、cell density 還是 high-fanout net
  • 調整 macro placement／orientation，加寬 channel 與 halo
  • 降低局部 placement density、cell spreading、加入 partial blockage
  • 改善 pin placement、buffer tree 與 layer utilization，必要時增加 core area
不要只回答「加大 die」；先找局部根因，因為加面積會直接傷 area/cost，也不一定能解決 macro pin access。
A09 IR drop 和 Electromigration（EM）有什麼不同？ ▼
問題核心物理可能後果常見改善
IR dropVdrop = I × Rcell 實際電壓下降、delay 增加、功能失敗加寬/加密 PG、更多 vias、decap、縮短供電路徑
EM電流密度過高造成金屬原子遷移void/hillock、長期可靠度失效加寬 wire、加 vias、分流、降低 peak current
兩者都和 current 有關，但 IR drop 偏向「電壓是否足夠」，EM 偏向「金屬長期能否承受該電流密度」。

SC02 如何用 Python 解析 PrimeTime timing report 並找出最差 path？ ▼ 
import re

def parse_timing_report(rpt_file):
    paths = []
    with open(rpt_file) as f:
        text = f.read()
    # 找每個 path block
    blocks = re.split(r'Startpoint', text)[1:]
    for block in blocks:
        slack = re.search(r'slack\s*\(([A-Z]+)\)\s*([\-\d.]+)', block)
        ep = re.search(r'Endpoint:\s*(\S+)', block)
        if slack and ep:
            paths.append({
                'endpoint': ep.group(1),
                'slack': float(slack.group(2)),
                'type': slack.group(1)
            })
    paths.sort(key=lambda x: x['slack'])
    return paths[:10]  # top 10 worst
  • Pandas 可以把多個 corner 的結果 merge，找跨 corner 的 worst case
  • 用 matplotlib 畫 slack histogram 幫助 CAD 判斷是否需要 ECO

SC04 現場給你 timing report，怎麼用 grep / awk / sed 找 violation？ ▼

1. 掃描 flow log 的錯誤

grep -nE 'ERROR|FATAL|FAIL' run.log
grep -c 'slack (VIOLATED)' timing.rpt

2. 取出最差的 violation slack

grep 'slack (VIOLATED)' timing.rpt \
  | awk '{print $NF}' \
  | sort -n \
  | head -10

3. 同時保留 endpoint 與 slack

awk '/^Endpoint:/{ep=$2}
     /slack.*VIOLATED/{print $NF, ep}' timing.rpt \
  | sort -n | head -10

4. 文字替換

sed -E 's/old_corner/new_corner/g' run.tcl > run_new.tcl
Report 欄位會依工具與選項改變。正式 automation 要先驗證格式、處理空檔／NA／多行 path，並讓 parser 在格式不符時明確 fail，而不是默默產生錯誤數字。
